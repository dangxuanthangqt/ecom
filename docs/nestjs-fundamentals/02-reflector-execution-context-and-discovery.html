Reflector, ExecutionContext và Discovery

Chương 1 dán nhãn. Chương này: ai đọc lại nhãn, đọc ở đâu, và đọc cả ứng dụng một lượt bằng cách nào.

01Reflector — bốn hàm, một bảng ẩn

Reflector là service của @nestjs/core, bên trong không có gì ngoài Reflect.getMetadata. Giá trị nằm ở bốn hàm tiện ích.

ví dụ: decorator Roles dán ở cả class và method 
const Roles = (...roles: string[]) => SetMetadata("roles", roles);

@Roles("admin")
class UserController {
  @Roles("seller") list() {}
  plain() {}
}
Gọi Kết quả Vì sao
get("roles", list) ["seller"] đọc đúng hàm list
get("roles", plain) undefined plain không có nhãn
getAllAndOverride("roles", [list, UserController]) ["seller"] list có giá trị → lấy, dừng
getAllAndOverride("roles", [plain, UserController]) ["admin"] plain là undefined → nhìn tiếp sang class
getAllAndOverride("roles", [UserController, list]) ["admin"] đảo thứ tự → class thắng dù list có nhãn riêng
getAllAndMerge("roles", [list, UserController]) ["seller", "admin"] hai mảng nối lại
Dùng Override khi

Nhãn là một quyết định: quyền cần, public hay không, mã HTTP. Method nói gì nghe method, không thì nghe class.

Dùng Merge khi

Nhãn là danh sách cộng dồn: nhiều role được phép, nhiều tag. Dự án dùng override cho mọi nhãn tự viết.

02Thứ tự targets là một hợp đồng
src/shared/guards/access-token.guard.tsdòng 77-79 
const required = this.reflector.getAllAndOverride<PermissionKey | undefined>(
  PERMISSION_KEY,
  [context.getHandler(), context.getClass()],   // ← handler TRƯỚC

[handler, class] — như dự án
  • Method có nhãn → dùng nó
  • Method không, class có → mặc định của controller
  • Cả hai không → undefined → guard trả 500 (chương 3)
[class, handler] — "dọn code" sai
  • Compile vẫn qua, test vẫn xanh nếu chưa controller nào dán cấp class
  • Ngày đầu tiên có nhãn cấp class → mọi method bị ghi đè
  • Không có lỗi, chỉ có 403 khó hiểu

undefined từ Reflector được biến thành mặc định ngay tại chỗ đọc, và mặc định là đóng (BEARER). Route không dán gì = route cần đăng nhập. Không ai phải nhớ dán @AuthApi([BEARER]).
03ExecutionContext — cửa sổ nhìn vào request đang chạy
"Request này là gì?" — từ ArgumentsHost 
context.getType()                    // "http" | "rpc" | "ws"
context.switchToHttp().getRequest()  // Express Request
context.switchToHttp().getResponse() // Express Response
context.getArgs()                    // [req, res, next]
"Sẽ rơi vào đâu?" — chỉ ExecutionContext có 
context.getClass()    // ManageProductController
context.getHandler()  // ManageProductController
                      //   .prototype.getManageProducts
Nơi Nhận Biết handler?
Guard canActivate(context) ExecutionContext Có
Interceptor intercept(context, next) ExecutionContext Có
Param decorator factory (data, context) ExecutionContext Có
Exception filter catch(exception, host) ArgumentsHost Không — lỗi có thể ném từ nơi chưa chọn handler
Middleware use(req, res, next) không có context Không — chương 4

Dự án dùng getType() ở global-exception.filter.ts:36 để phòng ngày có WebSocket gateway.

05Đọc cả ứng dụng một lượt: DiscoveryService + MetadataScanner

Reflector đọc nhãn của một handler đang được gọi. Hai việc cần đọc mọi handler khi chưa có request nào: boot-check "có route nào quên nhãn?" và seed "gom mọi key đã khai vào bảng Permission".

Mảnh (@nestjs/core) Cho bạn Lấy bằng
DiscoveryModule quyền dùng hai thứ dưới imports: [DiscoveryModule] — base.module.ts:104
DiscoveryService getControllers() / getProviders() → InstanceWrapper[] (.metatype, .instance, .name) inject
MetadataScanner getAllMethodNames(prototype) — kể cả method kế thừa inject
1 · discoveryService.getControllers()
Mọi controller DI container đã tạo. Lấy wrapper.metatype → class → .prototype.
2 · metadataScanner.getAllMethodNames(prototype)
Tên mọi method. Bỏ qua thứ không phải function.
3 · Reflect.getMetadata(PATH_METADATA, handler) === undefined → bỏ
Chỉ giữ method Nest đăng ký làm route. Helper private trên controller bị loại tại đây.
4 · reflector.getAllAndOverride(KEY, [handler, controllerClass])
Cùng hàm, cùng thứ tự như trong guard — cố ý. Boot-check và guard không thể lệch nhau về "route này cần gì".

06Chạy lúc nào: lifecycle hooks
Hook Chạy khi Dùng để
onModuleInit() module đó resolve xong dependency khởi tạo nội bộ một module
onApplicationBootstrap() mọi module đã init việc cần nhìn toàn app — quét controller
onModuleDestroy() / beforeApplicationShutdown() / onApplicationShutdown() tắt app đóng kết nối
Vì sao PermissionCoverageService dùng onApplicationBootstrap

Nếu dùng onModuleInit: lúc BaseModule init thì RouteModule có thể chưa → getControllers() trả danh sách thiếu → check xanh giả.

Hook chạy trong app.init(), không cần listen()

Script seed (create-permission.ts:22-23) gọi NestFactory.create → app.init() → hook chạy, controller có mặt, không bind port. Boot-check chạy ngay trong bước này → script seed cũng bị chặn nếu có route thiếu nhãn.

07Nâng cao
Decorator mang kiểu cho cả Reflector và Discovery (Nest 10.2+, có trong 11) 
// thay SetMetadata + hằng số
export const RequirePermission = Reflector.createDecorator<PermissionKey>();
reflector.get(RequirePermission, context.getHandler()); // đã có kiểu

// đánh dấu provider để lọc lúc quét
export const Job = DiscoveryService.createDecorator<{ cron: string }>();
discoveryService.getProviders({ metadataKey: Job.KEY });
discoveryService.getMetadataByDecorator(Job, wrapper);

Dự án chưa dùng — đây là hướng đi khi có loại metadata thứ ba, thứ tư.

Điểm mù: module lazy

DiscoveryService chỉ thấy những gì container đã tạo. Controller nạp qua LazyModuleLoader sau bootstrap thoát boot-check. Comment ở permission-coverage.service.ts:13-17 ghi rõ; guard vẫn trả 500 → điểm mù ồn ào, không im lặng.

Kế thừa và override

getAllAndOverride(KEY, [handler, class]) với handler kế thừa từ controller cha vẫn đọc được nhãn ở cha. Tận dụng cho BaseAdminController; nhưng method con không dán gì sẽ lấy nhãn cha.

Interceptor, pipe cũng đọc được

Cả hai nhận ExecutionContext. ClassSerializerInterceptor đọc @SerializeOptions() đúng cách này. "Route này cache 60s" = interceptor + SetMetadata("cache-ttl", 60).

Không cần cache kết quả Reflector

Bên dưới là WeakMap.get — nhanh hơn bất kỳ cache nào bạn tự viết.
